# UC-T09 — dynamic online ticket and protected eight-digit PIN

Validation 31/10/2026. Branch is based on current dev and preserves the team's offline-ticket, voucher and refund services.

- Backend 51/51 isolated tests pass, including the 33 T17/T21 regression tests. TypeScript, Vite production build and UTC regression pass on the corresponding frontend branch.
- Actual PayOS payment of 15,000 VND was confirmed for a one-hour S booking. An older running payment processor initially issued a six-digit legacy credential. No payment or booking status was forged or reset. The owner explicitly authorized the new authenticated `POST /api/bookings/{id}/ticket/upgrade-pin` action; the API rechecked PAID with PayOS and replaced the legacy credential once, with an audit record. Repeating the request did not change the new PIN/QR or payment.
- SQL persisted the protected eight-digit PIN and unique offline nonce. Two separate API processes using the same persisted key ring returned the same PIN. PINs, QR bearer values and key material are omitted from this report.
- Production React page and actual API/shared SQL were used. The QR image disappeared at expiry and changed automatically after server refresh; the PIN retained eight digits and its 4+4 display. Copy showed successful completion of the browser clipboard write; the automation clipboard bridge returned empty, so no independent paste comparison is claimed.
- Reading the separate offline ticket preserved the online QR, nonce, expiry and PIN. Completed booking responses hid online and offline credentials; the offline API refused reissuance, the page hid the QR/PIN and disabled copy/offline export.
- The PIN was accepted by actual Kiosk check-in and the current QR by Kiosk check-out (decoded payload entered through the production QR input, not an optical-camera scan). ESP32 relay/door events and SQL completed both physical door cycles; detailed T11/T12 evidence is recorded separately.
- Actual UI exposed a timezone defect: SQL timestamps without an offset were being read as Vietnam local time, incorrectly displaying overdue. The page now treats those timestamps as UTC and showed the real 15:20–16:20 rental period. Static compartment occupancy, station photo/location claims and fallback prices were removed from this page.
